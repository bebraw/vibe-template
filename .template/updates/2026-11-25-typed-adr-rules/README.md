# Query mutation scheduling and Local CI readiness

Use this pack to trace which local quality gates run mutation tests and when contributors should run Local CI. Each rule has its own decision history. Both appear in the same generated ADR index and CLI. [Architecture decision](../../../docs/adrs/implemented/ADR-076-pilot-typed-adr-rules.md) · [Query contract and schemas](../../../specs/adr-rules/spec.md)

## Apply

1. Inspect `patch.diff` and run `git apply --check <path-to-pack>/patch.diff` from the destination. The patch promotes Ajv 8.20.0 to a direct development dependency. If it applies, run `git apply <path-to-pack>/patch.diff`. If the manifest has diverged, add the exact Ajv pin to its development dependencies manually. The CLI also uses the template’s existing `yaml` 2.9.1 for frontmatter and Prettier 3.10.1 for Markdown headings. Use the project's pinned Node/npm to run `npm install`, review and commit the resulting lockfile, and verify a clean `npm ci`.
2. From the template revision containing this pack, copy the CLI and its helper modules and tests. List their exact paths in the template checkout with `git ls-files 'scripts/adr-rule*.mjs'`. Copy the two JSON Schema files and the feature contract under `specs/adr-rules/`. Review links and repository paths against the destination's existing layout.
3. Adapt `gateTerms` and `localCi` in the destination's quality-gate spec to its npm scripts and documented readiness cases. Record complete settings in each participating ADR's YAML frontmatter. Use the destination's decision numbers in `replaces`. If only the current policy is documented, start the chain with that decision. [Template glossary](../../../specs/quality-gate/spec.md)
   - For `local-mutation-testing`, record `gates` and cite the test that exercises current gate selection. The template chain is ADR-022 → ADR-025 → ADR-028 → ADR-043. ADR-025 narrowed the scope of `npm run quality:gate` while keeping its full mutation run. Use a new gate ID for a changed meaning and keep the previous definition with `retired: true`. Include only active gates in the current revision. [Current mutation decision](../../../docs/adrs/implemented/ADR-043-make-local-mutation-opt-in.md)
   - For `local-ci-readiness`, record `cases` with a shared outcome for any matching named case and an `otherwise` fallback. Cite the current written verification policy in `evidence`. The template chain is ADR-019 → ADR-025 → ADR-046, and its evidence is `AGENTS.md#verification`. [Current Local CI decision](../../../docs/adrs/implemented/ADR-046-scope-local-agent-ci-to-workflow-sensitive-changes.md)
4. Preserve existing ADR prose, lifecycle locations, supersession notes, and index summaries. Put `<!-- adr-rules:start -->` and `<!-- adr-rules:end -->` on separate lines in the destination ADR index's current-rules section. Adapt the CLI integration tests to the destination's decision histories, gate runner, and written Local CI policy. Record the pilot under its own decision number and add the opt-in criteria to the destination's agent instructions. [Integration tests](../../../scripts/adr-rules.test.mjs) · [Template agent instructions](../../../AGENTS.md#judgment-boundaries)

## Verify

- Run `node scripts/adr-rules.mjs local-mutation-testing` and `node scripts/adr-rules.mjs local-ci-readiness` to trace both decisions. Check that the mutation history shows the scope and command used at each revision. With `--json`, check active and retired definitions under `terms`, the ordered histories under `rules`, and the Local CI glossary under `localCi` when present.
- Run `node scripts/adr-rules.mjs --write-index`. Review the generated section, run `node scripts/adr-rules.mjs --check`, and confirm a second generation produces the same file.
- Run `node --test scripts/adr-rule*.test.mjs scripts/run-quality-gate.test.mjs` or the target's equivalent tests. Check which mutation command each gate schedules and compare the Local CI outcomes with the cited contributor instructions. Run the mutation command itself when you need its score.
- Run `npm run quality:gate` and `npm run ci:local`, or the target's equivalent quality and installation checks. Record `2026-11-25-typed-adr-rules` in the destination's applied update history after verification.
