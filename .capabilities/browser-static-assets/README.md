# Browser Module And Static Assets Capability Kit

Use this kit to add the smallest typed browser-module build and Cloudflare Workers static-assets path to a server-rendered Worker.

## Adds

- A TypeScript browser entrypoint that exposes a `data-browser-module="ready"` smoke-test hook.
- A separate browser `tsconfig` that emits native ES modules to `public/assets/`.
- One-shot and watch scripts using the target's pinned TypeScript compiler.
- A Wrangler custom build and static-assets configuration with Worker routes remaining authoritative.
- Static-response CSP and security headers plus revalidated caching for stable, unhashed module names.
- A JavaScript-enabled browser smoke test that executes the real entry module.

## Good Fit

- The target is a server-rendered Cloudflare Worker with no existing browser build or asset-serving convention.
- The client code is small enough that native ES modules are preferable to adopting a framework or bundler.
- The Worker remains the authority for HTML routes and static files are limited to supporting assets.

## Poor Fit

- The project already uses Vite, a framework adapter, import maps, or another client pipeline; integrate with that pipeline instead.
- The browser graph needs package bundling, hashed chunks, tree shaking, CSS processing, or broad legacy-browser transforms.
- Static assets need authentication or Worker middleware before every request; design `run_worker_first` and an assets binding for that route contract.

## Apply

1. Inspect the target's package scripts, TypeScript configs, Wrangler config, HTML response helpers, CSP, cache policy, public directory, and browser tests.
2. Follow `recipes/npm.md` and ask before adding or reconciling TypeScript or Playwright dependencies.
3. Copy or merge the files declared by `manifest.json`.
4. Add the external module tag to the server-rendered document and keep it out of the critical rendering path: `<script type="module" src="/assets/browser-entry.js"></script>`.
5. Add feature installers to `src/browser/browser-entry.ts`. Use explicit `.js` suffixes for relative imports so emitted modules resolve in browsers.
6. If progressive forms are wanted, apply `progressive-interaction` separately and install its enhancer from this entrypoint.
7. Run `checks.md` and the target's normal readiness gate.

The `_headers` file affects only static-asset responses. Keep equivalent CSP and security headers on HTML generated by Worker code.
